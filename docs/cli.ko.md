# 명령줄

**[English](cli.md) | 한국어**

채점은 명령 하나를 세 가지 이름으로 설치합니다: `chaejeom`, `Chaejeom`, `채점`.

| 명령 | 하는 일 |
|---|---|
| `chaejeom` | 대화형 터미널을 엽니다. `-c FILE`(또는 `--config FILE`)로 설정 파일을 불러와 시작합니다 |
| `chaejeom run` | 설정 파일과 데이터 파일로 평가를 한 번 실행합니다 |
| `chaejeom compare` | 두 결과 파일을 비교합니다 |
| `chaejeom list` | 지표와 각 지표에 필요한 입력을 보여 줍니다 |
| `chaejeom --version` | 버전을 보여 줍니다 |

API 키는 실행 폴더의 `.env` 파일이나 환경 변수의 `OPENAI_API_KEY`에서 읽습니다.

## `chaejeom run`

```bash
chaejeom run --config examples/eval.yaml --data examples/samples.jsonl
```

| 옵션 | 설명 |
|---|---|
| `--config FILE` | 설정 파일(YAML). 필수. [설정](configuration.ko.md) 참고 |
| `--data FILE` | 평가 데이터: JSONL, JSON, CSV. 없으면 `input/` 폴더에 하나뿐인 데이터 파일을 씀. [데이터 형식](data-format.ko.md) 참고 |
| `--out FILE` | 결과 파일. 기본 `output/<데이터 파일 이름>_<날짜-시각>.json`. 같은 이름의 CSV도 함께 저장 |
| `--runs N` | 반복 횟수. 설정 파일의 `runs`보다 우선 (기본 3). `--repeats`도 됨 |
| `--limit N` | 앞 N개 샘플만 평가. 내 데이터에서의 실제 비용을 먼저 확인할 때 씀 |
| `--label TEXT` | 이 실행의 이름. 결과 파일에 저장됨 (예: `검색기 v1.3`) |
| `--no-cache` | 캐시된 응답을 쓰지 않고 모델을 다시 호출 |

평가 전에 예상 비용을 보여 주고, 도메인 정보 없이 채점 지표를 돌리거나 평가 모델과 다른 곳으로 텍스트가 가게
되면 알려 줍니다. 평가 후에는 축별, 프레임워크별 점수표, 지표별 점수, 실제 토큰 사용량과 비용을 보여 줍니다.

성공하면 종료 코드 0으로 끝납니다. `--data`를 생략했는데 `input/`에 데이터 파일이 정확히 하나가 아니면 종료 코드
2로, 그 밖의 오류에는 종료 코드 1로 끝납니다. 설정 파일 오류, 모르는 지표나 옵션, 데이터 형식 오류, 없는 파일,
API 제공자 오류, 1보다 작은 `--runs`나 `--limit`이 여기에 해당합니다. API 키나 모델 이름이 틀려 모든 평가가
실패해도 결과 파일을 저장하지 않고 종료 코드 1로 끝나므로, CI에서 잡을 수 있습니다.

## `chaejeom compare`

```bash
chaejeom run --config eval.yaml --data samples.jsonl --label "검색기 v1.3" --out v1.3.json
chaejeom compare v1.2.json v1.3.json
```

`compare`는 두 결과의 축별, 프레임워크별 점수와 그 차이를 보여 주고, 이어서 점수가 0.25 이상 바뀐 샘플을 지표마다
최대 10개까지 변화가 큰 순으로 보여 줍니다. 샘플은 `id`로 맞추므로 샘플마다 바뀌지 않는 id를 붙여 두세요.
맞출 수 없었던 샘플 수도 알려 줍니다.

두 결과를 바로 비교할 수 없는 경우에는 경고합니다. 평가 데이터, 평가 모델이나 임베딩 모델, 도메인 정보 파일이나
수정본 프롬프트, 반복 횟수가 다르거나, 한쪽 파일에만 있는 지표가 있을 때입니다. 결과 파일마다 이것들의 지문이
기록되어 있습니다. 축 평균은 두 결과가 같은 지표들을 평균했을 때만 차이를 냅니다.

## 대화형 모드

```bash
chaejeom                  # 또는: chaejeom -c eval.yaml
```

`/`를 입력하면 명령 목록이 열리고, 데이터 파일 경로를 입력하면 바로 불러옵니다. 화면 언어는 기본이 영어이고
`/language ko`로 한국어로 바꿀 수 있습니다. 판정 설명은 언제나 한국어입니다.

| 명령 | 하는 일 |
|---|---|
| `/data [file]` | 평가 데이터 불러오기. 경로만 입력해도 같음. 경로 없이 입력하면 `input/` 폴더의 파일을 고르거나 Tab 자동 완성으로 경로를 입력 |
| `/metrics [ids]` | 축과 프레임워크로 나눈 격자에서 지표와 반복 횟수 선택 |
| `/model [model] [value]` | 평가 모델을 고른 뒤 temperature나 reasoning effort 설정 |
| `/temperature [0-2]` | 평가 모델의 temperature 설정. 추론 모델이 아닐 때만 보임 |
| `/effort [low\|medium\|high]` | 평가 모델의 reasoning effort 설정. 추론 모델일 때만 보임 |
| `/embedding [model]` | 임베딩 모델 선택 |
| `/domain [file\|off]` | 도메인 정보 파일 만들기, 불러오기, 보기, 끄기 |
| `/prompt [metric\|file]` | 모든 지표의 판정 프롬프트 보기, 채점 프롬프트 수정 |
| `/run [n]` | 평가 실행. 숫자를 주면 앞 n개 샘플만 |
| `/show [all\|sample [framework\|axis]]` | 샘플을 점수가 낮은 순으로 보거나, 샘플 하나의 점수, 판정, 판정 이유 보기 |
| `/runs [n]` | 반복 횟수 설정 |
| `/config [file\|save]` | 설정 파일 불러오기, 지금 설정을 파일로 저장 |
| `/language [en\|ko]` | 화면 언어 선택. 다음에 실행할 때도 기억함 |
| `/help` | 전체 명령 보기 |
| `/exit` | 종료. `/quit`, `exit`, `quit`, Ctrl+D, 빈 입력창에서 Ctrl+C 두 번으로도 종료 |

값을 생략하면 대부분의 명령은 선택 목록이나 입력창을 엽니다. 명령을 일부만 입력하고 Enter를 누르면 명령 하나와만
맞을 때만 실행하므로, `/r`이 실수로 `/run`을 시작하지 않습니다.

### 지표 고르기

`/metrics`는 축마다 한 행, 프레임워크마다 한 열인 격자를 엽니다. 방향키로 움직이고 Space로 칸 하나, 축 전체,
프레임워크 전체, 전부를 선택하거나 해제합니다. 반복 횟수(1에서 20)는 `Runs` 행에서
왼쪽, 오른쪽 방향키로 바꿉니다.
`/metrics ragas.*,chaejeom.groundedness`처럼 지표 id를 바로 적어도 됩니다. 입력창 아래 줄에 지금 고른 지표가 늘
표시됩니다.

### 모델

`/model`에서는 gpt-4o-mini, gpt-4.1-mini(기본), gpt-5-mini, gpt-5.4-mini, gpt-5.6-luna, gpt-6-luna를 고를 수
있습니다. 모델을 고른 뒤 일반 모델은 temperature(기본 0), 추론 모델은 reasoning effort(기본 `low`)를 정하며, 한
모델에는 둘 중 하나만 씁니다. `/embedding`에서는 text-embedding-3-small과 text-embedding-3-large(기본) 중에서
고릅니다. 임베딩은 RAGAS ResponseRelevancy에만 쓰입니다.

더 싸게 먼저 훑어보려면 `/model gpt-4o-mini`(단가 약 3분의 1, 도메인 지시는 덜 따름)나 `/runs 1`을 쓰세요.

### 도메인 정보 파일

`/domain`에서 서비스를 짧게든 자세히든 자유롭게 설명하면, 채점이 적은 내용을 서비스와 지표별 기준으로 정리하고,
정리한 항목과 그 항목이 판정 프롬프트에서 바꾸는 줄을 보여 준 뒤 확인을 받아 YAML 파일로 저장합니다. 말하지
않은 내용은 더하지 않고, 언급하지 않은 항목은 비워 둡니다. `5일`, `3%`처럼 정답이 될 수 있는 값은 정보의 종류로
바꾸고, 값이 남으면 다시 설명해 달라고 합니다.

메뉴에서 도메인 정보 파일 불러오기, 보기, 끄기와 설명을 정리할 모델 고르기(기본 gpt-4.1-mini, 평가 모델과 따로)도
할 수 있습니다. `/domain <파일>`은 파일을 바로 불러오고, `/domain off`는 끕니다. 도메인 정보 없이 채점 지표를
돌리려 하면 지금 설정할지, 일반 기준으로 돌릴지 묻습니다.

### 프롬프트

`/prompt`는 지표가 판정 모델에게 보내는 프롬프트를 요약해서 보여 줍니다. `{query}` 같은 입력 자리도 나오고,
*전체 프롬프트 보기*를 고르면 전부 볼 수 있습니다.

- **RAGAS, DeepEval, TruLens**: 원본 프레임워크에서 옮긴 그대로 두므로 볼 수만 있습니다.
- **채점**: *요청으로 수정하기*를 고르고 바꾸고 싶은 점을 적으면, 그에 맞게 프롬프트를 고쳐 `prompts/<지표 id>.yaml`
  (예: `prompts/chaejeom.groundedness.yaml`)로 저장하거나 지금 쓰는 프롬프트 파일을 덮어쓰고, 다음 `/run`부터 씁니다. 지표가 재는 것과 출력 형식은 바뀌지 않습니다. 도메인이 설정되어 있으면 도메인
  프롬프트에서 시작해 고칩니다. 프롬프트 파일 불러오기와 기본 프롬프트로 되돌리기도 할 수 있습니다.

저장한 파일은 Windows Terminal, VS Code처럼 링크를 지원하는 터미널에서 눌러서 열 수 있는 링크로 보입니다.

### 실행과 결과 보기

`/run`은 평가할 횟수와 예상 비용을 보여 주고, Enter를 누르면 시작합니다(Esc는 취소). 결과는 `output/`에
JSON과 CSV로 저장됩니다. 평가 중 Ctrl+C를 누르면 실행만 멈추고, 끝난 판정은 캐시에 남아 있어서 다시 실행하면 그
부분은 비용 없이 이어집니다. API 키나 모델 이름이 틀렸으면 오류로 가득한 표를 저장하지 않고 원인을 한 줄로 알려
줍니다.

점수표 아래의 *점수 없는 샘플*에는 지표가 점수를 내지 않은 샘플과 그 회차 수, 이유가 나옵니다. 대부분은 근거성에서
사실 진술이 없는 답변처럼 일부러 매기지 않은 경우이고, 오류는 빨간색으로 보여 줍니다.

`/show`는 평균 점수가 가장 낮은 샘플 15개를 축별 점수와 함께 보여 주고, 점수가 빠졌거나 오류가 난 샘플을
표시합니다(`/show all`은 모든 샘플). `/show q08`은 id나 데이터 안의 순서 번호(0부터)로 샘플 하나를 열어 점수와 판정, 판정 이유를
보여 줍니다. `/show q08 chaejeom`이나 `/show q08 groundedness`처럼 프레임워크나 축으로 좁혀 볼 수 있고,
`chaejeom.groundedness` 같은 지표 id도 됩니다. 여러 번 실행했을 때 회차마다 점수가 다른 지표는 옆에 회차별 점수가
나옵니다. `/config save <파일>`은 지금의 모델, 지표, 도메인 정보 파일, 프롬프트를 그 파일에 저장하고(경로가 없으면
`chaejeom.yaml`을 제안하며 물음), 이 파일은 `/config <파일>`이나 `chaejeom -c <파일>`로 다시 불러올 수 있습니다.
